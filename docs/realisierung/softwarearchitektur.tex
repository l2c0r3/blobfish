\section{Softwarearchitektur}

Nachfolgend wird mittels dem \gls{glos:c4} die Softwarearchitektur von blobfish dokumentiert.

\subsection{System context}

\begin{figure}[H]
    \centering
    \includegraphics[width=\linewidth]{generated-diagrams/c4-context}
    \caption{Softwarearchitektur - System context}
    \label{fig:c4-context}
\end{figure}

Angefangen mit dem Systemkontext, ist zu erkennen, dass es sich oberflächlich um ein einfaches System handelt: Ein Schachspieler,
welcher anhand einer CLI gegen einen Schachcomputer, blobfish, Schach spielt.

Da die Applikation eine Java-Applikation ist, als \gls{glos:uberjar} ausgeliefert wird und die Applikation ohne weitere \gls{glos:c4container}
auskommt, wurde auf das Container Diagram verzichtet, das keinen wirklichen Mehrwert gegenüber dem Context-Diagramm bietet,
da es praktisch dasselbe ist.

\subsection{Component}

\begin{figure}[H]
    \centering
    \includegraphics[width=\linewidth]{generated-diagrams/c4-component}
    \caption{Softwarearchitektur - Component diagram}
    \label{fig:c4-component}
\end{figure}

Anhand des Component-Diagramms sind die 4 Packages und deren Abhängigkeit untereinander zu.

Das \textit{base} Package enthält grundlegende Datenstrukturen wie das \texttt{ChessBoard}, \texttt{Piece}, Interfaces sowie Util Klassen.
Desweiteren wrapped sie primär mit der \texttt{ChessBoard} Klasse die \texit{chesslib}, welche unter anderem für die Zuggenerierung
und Spiellogik verwendet wird.

Das Package \textit{eval} oder \textit{minimax} sind sehr spezialisiert. So beinhaltet \textit{eval} die Heuristiken, um
Schachpositionen zu bewerten und \textit{minimax} unterschiedliche Implementierungen des Minimax-Algorithmus. \\
Auffällig dabei ist, dass beide Packages keine direkte Abhängigkeit miteinander haben, was so bewusst implementiert wurde.
Die Verbindung zwischen den beiden Packages wird über das Interface \texttt{EvaluationStrategy} aus dem \texttt{base}-Package hergestellt,
welches die Kopplung zwischen Bewertungslogik und Suchalgorithmus auflöst.

Das \textit{game} Package enthält sämtliche Klassen und Logik für die CLI-Applikation. Sei es der Game-Flow, die UI Darstellung
oder die Terminal-Interaktion, wofür zusätzlich \textit{jline} verwendet wurde.

\subsection{Code}

Beim Code wird der Fokus auf zwei Packages gelegt: \textit{eval} und \textit{minimax}, um einen Überblick von der Implementierung
zu erhalten.

\subsubsection{Positionsbewertung}

\begin{figure}[H]
    \centering
    \includegraphics[width=\linewidth]{generated-diagrams/eval-code}
    \caption{Softwarearchitektur - eval}
    \label{fig:softwararchitecture-eval}
\end{figure}

Der Code für die Bewertung von Spielpositionen befindet sich bis auf das Interface \texttt{EvaluationStrategy} im \textit{eval}
Package. Dafür steht in der Darstellung exemplarisch \textit{PiececSquareEvaluation}. Die restlichen Heuristiken sind
übersichtshalber nicht dargestellt. \\
Um mehrere Heuristiken zu kombinieren, wurde die Klasse \textit{CompositeEvaluationStrategy} implementiert. Über das
Builder-Pattern können fluent \textit{EvaluationStrategy} Implementationen übergeben werden und über die \textit{getEvaluation}-Methode
zu einer Gesamtbewertung zusammenfasst werden. \\
Mittels dieses Designs können einfach weitere Heuristiken implementiert und beliebig kombiniert werden, ohne bestehenden Code anpassen
zu müssen.
